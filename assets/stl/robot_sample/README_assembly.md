# GLCE 3-Link Robot Arm — STL v2 (normal/finger correction)

**Change from v1**
- Corrected the inverted box triangle winding that produced inward-facing normals in v1.
- Rebuilt all six parts with solid Boolean unions, removing overlapping internal faces within each part.
- Made each left/right finger **a single rectangular prism**, instead of the prior multi-shape finger.
- Kept rotation-center local origins and the same recommended parent→child offsets as v1.
- Exported six **ASCII STL** files to match the GLCE STL ASCII loader.

## Units and coordinate conventions

- Dimensions: mm (STL does not encode units; treat 1 STL unit = 1 mm).
- Right-handed XYZ coordinates.
- Zero pose: all child rotations `(0, 0, 0)` and link longitudinal direction +X.
- Every STL is authored relative to **its own joint pivot origin**, not the robot world origin.
- STL has no material or color payload; assign a diffuse material per mesh in GLCE.

## Suggested coordinate tree

```text
Root [0]                   (auto-generated by render_model constructor)
  └─ Base [1]               -> 01_base_rotation_joint.stl
      └─ Shoulder [2]       -> 02_shoulder_link.stl
          └─ Elbow [3]      -> 03_elbow_link.stl
              └─ Wrist [4]  -> 04_wrist_gripper_base.stl
                  ├─ Left finger [5]   -> 05_left_finger.stl
                  ├─ Right finger [6]  -> 06_right_finger.stl
                  └─ TCP [7]           -> no mesh (optional)
```

## Verification

Each STL was checked for ASCII encoding, triangle winding consistency, outward signed volume, being watertight, and containing exactly one connected component. **This checks surface topology, not physical collision clearance between separately moving parts.** See `validation.json` for per-part results.

The `source/` folder contains the OpenSCAD source used to produce the solids for reproducible edits.
